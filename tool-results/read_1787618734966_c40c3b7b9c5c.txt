     8→## 📋 Resumen Ejecutivo
     9→
    10→**En Santiago** es un directorio metropolitano de negocios de Santiago de Chile construido sobre Cloudflare Pages + Functions, con base de datos D1, almacenamiento R2, e integración con Workers AI. Incluye también un sub-sistema de Inmobiliaria, Marketplace, Empleo, Academia de Agentes y Chat IA.
    11→
    12→**URL producción**: `https://en-santiago.pages.dev`

    16→## 🏗️ Arquitectura
    17→
    18→### Stack
    19→- **Hosting**: Cloudflare Pages (con Pages Functions)
    20→- **Runtime**: Cloudflare Workers (V8 isolates, sin Node.js nativo)
    21→- **DB**: Cloudflare D1 (SQLite distribuido)
    22→- **Storage**: Cloudflare R2 (compatible S3, sin egresos)
    23→- **AI**: Cloudflare Workers AI (modelo `@cf/meta/llama-3.1-8b-instruct`)
    24→- **Frontend**: HTML estático + JavaScript vanilla (sin React/Vue)
    25→- **Auth**: JWT HMAC-SHA256 firmado en edge, almacenado en `localStorage`
    26→
    27→### Bindings (definidos en `wrangler.toml`)
    28→
    29→| Binding | Tipo | Recurso |
    30→|---|---|---|
    31→| `DB` | D1 database | `en-santiago-db` (ID: `083ae5ed-b15f-4ff3-abcf-b3a3b666bb79`) |
    32→| `R2` | R2 bucket | `en-santiago-media` |
    33→| `AI` | Workers AI | Llama 3.1 8B Instruct |
    34→| `JWT_SECRET` | Var | `ensantiago_jwt_secret_2024` |
    35→| `R2_FOLDER` | Var | `santiago` |

   136→## 🔐 Sistema de Autenticación
   137→
   138→### Flujo
   139→
   140→1. **Login**: `POST /api/auth/login` con `{email, password}` → valida `password_hash` (PBKDF2) → retorna JWT
   141→2. **JWT**: HMAC-SHA256 firmado con `env.JWT_SECRET` (3 partes: header.payload.signature, base64url)
   142→3. **Storage**: Frontend guarda en `localStorage` con keys `ensantiago_token` y `ensantiago_user`
   143→4. **Requests autenticadas**: Header `Authorization: Bearer <jwt>`
   144→5. **Verificación server-side**: `getUserFromRequest(request, env)` en `functions/_lib/auth.js`
   145→6. **Admin check**: `requireAdmin(request, env)` verifica `user.role === 'admin'`
   146→7. **Owner check**: en endpoints de businesses/properties, compara `user.id === business.user_id` O `user.role === 'admin'`
   147→
   148→### Roles
   149→
   150→- `user` — Usuario normal, puede publicar negocios, productos, propiedades
   151→- `admin` — Acceso total: panel admin, crear/editar categorías, aprobar/rechazar contenidos, gestionar usuarios
   152→- `seller` — Vendedor con sub-usuarios (`seller_owner_id` apunta al usuario padre)
   153→- `agent` — Agente del programa AunClick Academy (gamificado con XP, badges, clases)
   154→
   155→### Endpoints de Auth
   156→
   157→- `POST /api/auth/register` — Registro email+password
   158→- `POST /api/auth/login` — Login email+password
   159→- `POST /api/auth/google` — Login/registro con Google ID token
   160→- `GET  /api/auth/google-config` — Config Google OAuth (público)
   161→- `GET  /api/auth/me` — Datos del usuario actual
   162→- `POST /api/auth/promote-me` — Auto-promover a admin (debug only, debe desactivarse en prod)

   166→## 🌐 Endpoints API (Mapa Completo)
   167→
   168→### Estructura: `functions/api/<dominio>/<recurso>.js`
   169→
   170→Cada archivo exporta handlers: `onRequestGet`, `onRequestPost`, `onRequestPut`, `onRequestDelete`, `onRequestOptions`.
   171→
   172→### 🔐 Convenciones de seguridad
   173→
   174→- **Público**: sin auth. Listados, fichas, páginas SSR.
   175→- **Auth requerida**: header `Authorization: Bearer <jwt>`. Crear/editar contenido propio.
   176→- **Admin only**: requiere `user.role === 'admin'`. Gestionar categorías, usuarios, aprobar contenido.
   177→- **Owner**: el `user.id` debe coincidir con el `user_id` del recurso.

   542→
   543→### Bug 1: Slug de categoría no se regenera al editar nombre
   544→
   545→**Síntoma**: Al renombrar una categoría (ej: "Tapizados de Volantes" → "Tapizar IA"), el `slug` en DB seguía siendo el viejo, rompiendo `/categoria/:slug`.
   546→
   547→**Fix**: `functions/api/categories/[id].js` ahora regenera slug cuando `name` cambia. `functions/categoria/[slug].js` hace fallback por `slugify(name)` + 301 redirect. Modal de edición en `js/admin.js`.
   548→
   549→**Commit**: `a511933`
   550→
   551→### Bug 2: Cambiar categoría de un negocio rompía la URL vieja
   552→
   553→**Síntoma**: Al mover un negocio de "Otros" a "Tapizado de Volantes", la URL vieja `/servicios-varios/otros/mi-negocio` daba 404 porque la query SQL filtraba por `c.id = ?` (la categoría de la URL vieja).
   554→
   555→**Fix**: `functions/[tipo]/[categoria]/[slug].js` ya no filtra por `c.id`. Busca solo por `slug` + `status='approved'`. Si la URL no coincide con los datos actuales, redirect 301 a la URL canónica.
   556→
   557→**Commit**: `6258cad`
   558→

   560→

   562→
   563→**Fix**: `functions/_lib/render-business.js` mueve la descripción a sección "Sobre el Negocio" después del botón "Sitio Web". CSS `text-align: justify`. Sin collapse ni degradado.
   564→
   565→**Commits**: `a468ab6`, `6e27b53`
